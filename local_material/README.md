# 本地一次性材料模式

这是当前讨论的 TEE 辅助方案的**本地功能实现**。运行于 WSL/Linux，无需云服务器或 SGX。
模式固定标记为 `local-simulation-NOT-TEE`。三个进程及协调器均为普通软件：宿主可以读内存，协调器也能看到秘密种子。没有远程证明、保密通道和可信擦除，不能称为真实 TEE 安全或性能实验。

## 运行

在 Ubuntu/WSL 仓库根目录执行：

```bash
cd /home/ph/single-server-pir
bash local_material/run_local_validation.sh
```

脚本运行 6 个相关测试目标，再以优化构建执行 5 次小规模查询和 3 次 8 MB 查询，输出 `local_material/results/{functional,8mb,manifest}.json`。首次编译需要构建依赖。

```bash
# 只运行小规模流程
bazel run -c opt //local_material:local_worker -- demo 5 functional
# 8 MB 配置，10 次查询
bazel run -c opt //local_material:local_worker -- demo 10 8mb
```

这些命令不访问云服务器。构建工具可能需要下载 WORKSPACE 中声明的公开依赖。

## 分工与流程

| 组件 | 职责与输入 | 不接收的内容 |
|---|---|---|
| `PreparedClient` | 随机种子、一次性状态、选索引、LWE 查询、恢复密钥、CRT/LWE 解密 | 不从生成器取回大体积材料 |
| `LocalMaterialGenerator` | 数值参数、公开 RLWE 种子、材料 ID、秘密种子；生成 Enc(s) 和完整 GK | 数据库 D、完整 A、H、静态响应 hint、查询索引 |
| `PreparedServer` | 数据库、预计算、材料缓存；计算 Dq 与加密 Hs，返回 b 分量 | 秘密种子、s、v |
| `local_worker` | 三个独立子进程，通过 Unix socket 传输长度前缀 protobuf；核验记录并输出 JSON | 不提供真正的隔离或认证 |

1. 服务端设 `session_pool_capacity=1`，生成一份静态公开响应分量。这里的 1 表示公共预计算只有一份，**不限制材料或查询总数**。
2. 客户端 `BeginPreparation()` 创建 32 字节随机秘密种子及材料 ID，状态为 PENDING，无需决定索引。
3. 生成器通过 HKDF-SHA256，按配置、ID 和 `LWE-secret` / `RLWE-secret` 标签派生独立随机流，生成 s、v。RLWE 加密和 GK 噪声由底层库每次独立随机采样，不从公开 seed 获取，也不复用 LWE 秘密随机流。
4. 生成器输出公开材料，服务端安装。客户端核对生成回执和安装回执后进入 READY。摘要仅用于模拟一致性，**不是认证或远程证明**。
5. 客户端随后选索引，原子预留材料，生成并保存唯一请求，进入 IN_FLIGHT。请求只有配置 ID、材料 ID、请求 ID 和 LWE 查询。
6. 服务端取出 Enc(s) 和对应 GK，交给原求值逻辑。同一材料至多求值一次。
7. 客户端重组在线 b 和静态 a，使用对应 v 解密、CRT 恢复 Hs，从 Dq 中减去它，舍入并重组记录。
8. 客户端完成后进入 DONE。服务端释放材料和评估密钥；`Release()` 进一步释放缓存响应，保留已消费标记。

库存可以持续补充。演示中的下一次索引根据上一次结果选择，生成器始终不知道索引。
底层 `Client::CreateForPreparedMaterial` 是安装确认之后调用的适配器，应用应使用 `PreparedClient`。在线客户端只恢复 RLWE 解密密钥，不执行 Enc(s) 或 GK 生成。

## 生命周期与接口边界

- PENDING → READY → RESERVED → IN_FLIGHT → DONE；失败或放弃进入 INVALID。
- 新索引、新噪声或新请求 ID 必须使用新材料。`Retry()` 返回已经保存的原请求；服务端仅对逐字节一致且缓存仍在的请求返回原响应。
- 同一材料并发调用不会重复消费；多个客户端共享同一公开预计算。当前服务端持锁求值，并发测试验证一致性，**没有实现并行吞吐优化**。
- 配置摘要绑定数值参数、数据库版本、公开随机性和静态响应分量。`Refresh()` 重做预处理，旧材料全部失效。
- 本版状态只在内存中，**没有持久化恢复接口**。客户端重启放弃库存；服务端重启生成新配置。不得自行恢复旧 seed/ID/配置文件；不声称抵抗快照、克隆或回滚。
- 已消费标记随查询数增长，配置重设后清空。长期大规模服务还需持久化、容量限制及回收策略。

`protocol.h/.cc` 是接口与实现；`serialization.proto` 分离秘密准备消息、公开材料和在线查询；`protocol_test.cc` 验证状态及真实底层密码运算。

## 参数与结果口径

| 配置 | 数据库 | LWE 维度 | 明文 CRT 模数 | 用途 |
|---|---|---|---|---|
| functional | 8×8 条，每条 8 字节，共 512 字节 | 32 | 2056193、1990657 | 快速功能测试，无实用安全级别声明 |
| 8mb | 1024×1024 条，每条 8 字节，共 8 MiB | 1024 | 2236417、2277377 | 与原稿维度一致的规模及正确性验证；安全级别与失败概率尚未估算 |

均使用 32-bit LWE 运算、8-bit 数据库片、三元 LWE 秘密和库实际采用的方差 8 查询噪声。RLWE 环次数 4096，密文 RNS 模数为 35184371884033、35184371703809。

平衡表示的 H 和三元 s 满足 |Hs| ≤ n·2^31，因此检查 **CRT 乘积 P > n·2^32**。原来的 2056193、1990657 两个素数乘积比 n=1024 的确定性充分界少约 6.9%。8 MiB 档改用同样支持 4096 阶环 NTT 的 2236417、2277377；两者乘积比该界高约 15.8%，无需第三个 CRT 分支。这个检查只解决整数 CRT 唯一重构范围，不等于完成 LWE/RLWE 安全估参或噪声失败率证明。

JSON 分别记录首次公开参数、种子、两份回执、在线请求、在线响应、释放控制、服务端内部材料和所有进程间帧字节。`logical_client_payload_total_bytes` 包含客户端相关应用消息，**不包含未实现的证明、加密通道及真实网络开销**；这些缺失成本写为 `null`，不写成 0。

`all_worker_ipc_framed_bytes_including_test_oracle` 是整个验证工具的帧字节数，包含协调器转发和测试 oracle，不能当作协议客户端网络流量。`expected` 测试命令会将索引交给服务器检查记录，部署版本必须删除它。

`summarize_results.py` 核对总字节账目、RLWE 在线分量与静态分量是否等大，并记录源码指纹与平台。少量运行的时间数组只是本机观测，不支持 P95/P99、网络性能或真实 TEE 开销结论。

## 尚未覆盖

独立 v 消除了原相减攻击中的同一掩蔽项直接抵消，但测试通过不是完整多查询证明；固定公开随机项、相关评估密钥及多 CRT 分支仍需联合论证。

显式清理了部分派生 seed，并释放已消费材料的内存；上游密码库、protobuf、OS 与协调器仍可能留有秘密副本，不能声称可信擦除或“事后攻破无泄露”。真实 TEE、认证保密通道和持久化恢复未实现，本次交付范围是本地验证。

静态公开响应分量预计算沿用 HintlessPIR 的已有构造。旧公共掩码池/会话密钥方案仍保留在 `hintless_simplepir/SECURE_SESSION.md` 和旧测试中供对照，新入口使用本目录的一次性独立密钥方案。
